# Changelog

Chronologisches Protokoll aller Änderungen am Projekt — neuester Eintrag oben. Zweck: nachvollziehen können, was wann gebaut und ob es tatsächlich geprüft wurde.

## Format

```
## YYYY-MM-DD — AP <Nummer>: <Titel des Arbeitspakets>
- Geändert: <was konkret entstanden oder angepasst wurde, mit Dateien/Bereichen>
- Verifikation: <bestanden / offen / teilweise> — <wie geprüft: npm run build, Browser-Check, RLS-Test, Advisors>
```

Regeln:
- **Ein Eintrag pro Arbeitspaket**, geschrieben direkt nach der Verifikation — nicht gesammelt am Ende des Tages.
- Die Spec- bzw. Arbeitspaket-Nummer aus `implementierungsplan.md` immer mitschreiben, damit Eintrag und Plan verknüpft bleiben.
- **Verifikationsstand ehrlich vermerken.** „Offen" ist ein gültiger Eintrag, „bestanden" ohne durchgeführte Prüfung nicht.
- Fehlgeschlagene oder zurückgerollte Änderungen bleiben stehen und bekommen eine Folgezeile, statt gelöscht zu werden.
